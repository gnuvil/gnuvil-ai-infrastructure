# 아키텍처

Proxmox VE는 Ubuntu 24.04 VM과 NVIDIA Tesla V100 패스스루를 제공한다. VM의 Ansible은 로컬 연결로 Ubuntu 구성, 영구 데이터 경로, 드라이버와 컨테이너 런타임을 관리한다. 원격 제어로 옮길 때는 인벤토리의 연결 방식을 SSH로 바꾸고, 컨트롤 노드에 Ansible과 컬렉션을 준비한다. 명시적 CUDA 검증에는 대상 VM에 체크아웃한 프로젝트가 필요하다.

Compose는 루트의 `include`를 통해 서비스별 상대 경로의 빌드 컨텍스트를 유지한다. 첫 서비스는 포트와 영구 볼륨을 사용하지 않는 `gpu-smoke`다. 실제 서비스가 추가되면 서비스를 별도 디렉터리에 두고, CPU 서비스에는 GPU 할당을 생략한다. GPU가 필요한 서비스는 서비스명과 동일한 프로필, `restart: "no"`, 이미지 빌드 및 GPU 정책 항목을 함께 선언한다. 장기 실행 서비스 도입 시 전환기에 해당 서비스의 준비 상태와 종료 절차를 추가한다.

## GPU 사용

`configs/gpu-policy.yaml`에 GPU 서비스 목록과 종료·유휴·테스트 대기 시간, 유휴 VRAM 상한을 선언한다. `switch`와 `gpu-off`는 VM의 `/run/gnuvil-ai-gpu.lock`을 공유한다. GPU 연산 프로세스가 없고 VRAM 사용량이 기준 이하일 때만 새 컨테이너를 시작한다. VRAM 기준의 기본값은 64 MiB다. VM에서 정상 유휴 사용량을 측정한 뒤 필요한 경우 정책을 조정한다.

컨테이너 안에서 진행되는 추론과 학습의 작업 상태는 이 초기 구현에서 조회할 수 없다. 운영자는 `make status`로 확인하고 작업을 비운 뒤에만 `CONFIRM=1`을 지정한다. 전환기는 SIGTERM을 보내고 종료를 기다린다. 제한 시간 안에 종료되지 않거나 VRAM이 회수되지 않으면 대상 서비스 시작을 중단한다. CUDA 테스트가 시간 초과되면 상태와 로그를 확인한 뒤 조치한다.

상호 배제는 전환기를 사용하는 요청 사이에 적용된다. 운영 중에는 GPU 서비스를 전환기를 통해 실행한다. 직접 실행한 Docker 컨테이너, 호스트 프로세스, 다른 Compose 프로젝트는 잠금 범위 밖에 있다. 그런 프로세스가 이미 GPU를 사용 중이면 유휴 확인 단계에서 전환을 차단한다. Compose Profile 자체는 물리 GPU를 독점하지 않는다.

## 데이터와 권한

프로젝트 `/opt/gnuvil-ai`와 데이터 `/srv/ai-data`는 분리한다. 스토리지 Role은 다음 디렉터리를 만든다.

| 경로 | 용도 |
| --- | --- |
| `models/` | 검증된 모델 파일 |
| `datasets/` | 학습용 원본 및 가공 데이터 |
| `outputs/` | 생성 및 추론 결과 |
| `cache/` | 다시 만들 수 있는 다운로드·런타임 캐시 |
| `state/` | 사용자 DB 및 서비스 상태 |
| `logs/` | 앱에서 파일로 기록하는 로그 |

데이터 루트 모드는 `0750`, 하위 디렉터리는 `2770`이다. 기본 소유권은 `root:root`다. 이후 서비스가 추가되면 전용 UID/GID를 정하고 필요한 하위 경로에만 권한을 준다. 모델 파일은 가능한 읽기 전용으로 마운트한다. 인증 토큰과 시크릿은 승인된 별도 보관소에 둔다. Docker 그룹은 실질적으로 root 권한을 주므로 Playbook은 일반 사용자를 추가하지 않는다.

모델 매니페스트를 도입할 때는 서비스와 모델 식별자, 고정 소스 URL 및 revision, 파일명, 양자화 형식, SHA-256, 라이선스를 기록한다. 모델 획득 및 해시 검증은 VM 구성과 별도의 명령으로 제공한다.
