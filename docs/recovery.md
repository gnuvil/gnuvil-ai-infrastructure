# 재구축 및 복구

운영 기준선으로 Git 커밋 SHA, Ubuntu 커널, 설치된 APT 버전, 데이터 파일시스템 UUID 및 데이터 UID/GID를 기록한다. 별도 변수 파일, 서비스 자격 증명, 외부 마운트 설정은 복구 가능한 별도 보관소에 저장한다.

## 백업

- `/srv/ai-data`의 `models/`, `datasets/`, `outputs/`, `state/`를 백업한다. `logs/`는 운영 정책에 따라 보관하고 `cache/`는 재생성 가능한 항목을 분리한다.
- DB와 학습 작업의 일관성을 확보하려면 서비스가 지원하는 백업 방법을 사용하거나 작업을 정상 종료한 뒤 스냅샷을 찍는다. ZFS RAIDZ1 풀 외부에 백업을 보관하고, 해당 백업으로 복원 시험을 수행한다.
- 모델은 재다운로드할 수 있는 파일과 별도 보관할 파일을 구분한다. 향후 매니페스트가 도입되면 복원한 파일의 SHA-256을 검증한다.

## 복구 순서

1. 동일한 패스스루와 Guest Agent 채널을 가진 Ubuntu Server 26.04 LTS 표준 amd64 VM을 준비한다.
2. 마지막으로 검증된 Git 커밋을 `/opt/gnuvil-ai`에 체크아웃하고 운영 변수를 복원한다.
3. 데이터를 연결하고 UUID, 파일시스템, 대상 경로를 확인한다. 기존 데이터 디스크가 살아 있다면 파일시스템을 그대로 마운트한다. 백업을 새 디스크로 복원하는 경우 운영자가 대상 파일시스템을 준비한 뒤 권한, 소유권, ACL을 보존하여 복원한다.
4. [설치 절차](installation.md)에 따라 bootstrap과 configure를 적용하고 재부팅이 필요하면 진행한다. 적용 전에 스토리지 설정이 데이터를 복원한 실제 마운트를 가리키는지 확인한다.
5. 데이터 경로의 읽기 권한, 서비스별 상태 및 백업 체크섬을 확인하고 GPU 스모크 테스트를 실행한다. 실제 AI 서비스는 각 서비스의 복구 확인을 끝낸 후 시작한다.

버전이 upstream에서 없어졌다면 검증된 패키지 스냅샷을 사용한다. 대체 버전을 선택하는 경우 [호환성](compatibility.md)의 제약을 기준으로 새 VM에서 검증한 뒤 잠금값과 운영 기록을 갱신한다.
